Worth keeping, not yet worth trusting blind. Where CodeRabbit reviewed, 38 % of its inline findings were real defects or contract violations and 39 of those 43 got fixed. But 18 % were wrong, and 15 of the 20 wrong ones come from five repeat patterns that our own configuration can remove.

The bigger problem is coverage. Since 8 Sep 06:29 UTC CodeRabbit no longer auto-reviews public repositories with fewer than 10 stars. That is 33 active repos, including nearly every platform service, and 58 % of the human PR flow.

Proposed config changes, ready to paste

# .coderabbit.yaml (excerpt)
reviews:
  pre_merge_checks:
    title:
      mode: "error"
  auto_review:
    base_branches:
      - "release/.*"
      - "test/.*"
      - "dev/.*"
      - "feature/.*"
  tools:
    languagetool:
      enabled: false
  path_instructions:
    - path: "**/*.cs"
      instructions: >-
        … existing text … Do NOT flag a null-forgiving `!` in test code
        (tests/**) when the preceding assertion already fails on null
        (Assert.NotNull, Should().NotBeNull(), Assert.That(x).IsNotNull()).
        Before calling a public-API change a breaking change, confirm the
        API exists on the default branch; code that never reached main has
        no consumers.
    - path: "**/*.md"
      instructions: >-
        Documentation is English-only and durable. Flag transient problem
        notes ONLY on lines this PR adds or rewrites. A bare work-item
        reference (AB#nnnn) may stay. A documented, tracked product
        limitation is durable, not transient. Review a code example once
        for correctness; do not iterate on its idiom across follow-up PRs.

How this was measured

Deterministic layer

  • GraphQL and REST dump of all 275 PRs: reviews, review threads, replies, reactions, commits, timing.
  • Per PR: CodeRabbit status (reviewed, summary only, skipped with reason, absent), review events, actionable and nitpick counts, learnings, guideline citations, pre-merge check results, rate-limit and overage markers.
  • Per thread: severity and category from the comment header, author reply, bot confirmation or withdrawal, resolution.

Judgement layer

  • Seven agents read the 123 threads in PR dossiers (with local checkouts for code checks) and classified validity, substance, observed outcome, root cause and the config lever.
  • One skeptic agent tried to refute all 24 "wrong" verdicts; it overturned 3 to "correct but minor".
  • Heuristic acceptance from replies alone was 53 %; the judged substantive rate is 38 % because many "fixed" replies were compliance with wording nits.

The scripts (dump, metrics, batch dossiers, classification workflow, aggregation) live in the audit/ folder of the central configuration repository; its README describes the monthly rerun.
